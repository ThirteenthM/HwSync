# Утилита управления сервером

HwSync.Windows.Admin.Application — отдельное Windows-приложение для пользователя управления.
Оно не является участником синхронизации, не создаёт собственную SQLite и не сканирует папки.
Все сведения получает через административный API HwSync.Windows.Server.Host.

## Первый запуск из Visual Studio

1. Выполните в PowerShell из корня репозитория:

       .\scripts\New-AdminAccess.ps1 -Name administrator

   Скрипт ничего не сохраняет и не меняет. Он показывает персональный AccessToken и объект ServerUser.
   Сохраните ключ отдельно: по хешу на сервере восстановить его нельзя.

2. В src/HwSync.Windows.Server.Host/appsettings.json поместите **только объект ServerUser** в массив Administration.Users:

       "Administration": {
         "Users": [
           {
             "Name": "administrator",
             "TokenSha256": "сюда значение TokenSha256 из результата скрипта",
             "CanRead": true
           }
         ]
       }

   Сам AccessToken в конфигурацию и Git не добавляйте.
   Каждый пользователь должен иметь собственный ключ. Пустой массив закрывает доступ всем.
   Вместо файла можно задать Administration__Users__0__Name,
   Administration__Users__0__TokenSha256, Administration__Users__0__CanRead
   в окружении процесса сервера.

3. Пересоберите и запустите HwSync.Windows.Server.Host в консольном режиме, как описано в HOST.md.
   Для надёжного применения изменений доступа перезапустите сервер.

4. Запустите HwSync.Windows.Admin.Application, оставьте адрес http://localhost:5080/,
   задайте AccessToken в переменной окружения HWSYNC_ADMIN_ACCESS_TOKEN до запуска приложения и нажмите «Подключить / обновить».
   Ключ хранится только в памяти до закрытия утилиты. В файл настроек он не записывается.

Для запуска из терминала:

    dotnet run --project src/HwSync.Windows.Server.Host -- --console
    dotnet run --project src/HwSync.Windows.Admin.Application

Команды запускайте в разных терминалах. Второй экземпляр сервера запускать не требуется.

## Что показывает приложение

- «Настройки сервера»: имя пользователя управления, компьютер сервера, версия сборки API,
  фактические адреса прослушивания, путь серверной SQLite, уровень журналирования и ограничение доступа.
  Это выбранные параметры для просмотра, не выгрузка всей конфигурации.
- «Папки и похоронная книга»: каталоги, уже зарегистрированные успешным сканированием,
  число файлов в последнем сохранённом снимке и число активных записей удаления.
- Выберите папку и нажмите «Показать историю». Журнал читается по 100 событий;
  «Следующие 100 записей» добавляет очередную страницу.
- Для события показываются номер, относительный путь, активность, время удаления и прежнего изменения
  в UTC, размер последней известной версии в МБ (1 МБ = 1 000 000 байт, три знака после разделителя),
  идентификатор участника, записавшего удаление.
- «Отменить запрос» прерывает загрузку. Смена адреса или ключа очищает данные предыдущего подключения.

Активная запись означает действующую отметку удаления. Неактивная означает, что при последующем
сканировании файл снова присутствовал. Это не подтверждение доставки удаления всем участникам.
Идентификатор участника-источника не является именем пользователя управления.

Папки не ищутся автоматически на дисках. Если список пуст, сначала выполните сравнение в клиенте
синхронизации. Данные отражают сохранённые снимки; утилита не запускает сканирование.
Время последнего сканирования текущая схема SQLite не хранит и утилита его не придумывает.
Похоронная книга не содержит самих файлов и не является корзиной.

## Настройки утилиты

Рядом с приложением находится appsettings.json:

    {
      "ServerAddress": "http://localhost:5080/",
      "RequestTimeoutSeconds": 30
    }

Тайм-аут допустим от 1 до 3600 секунд. Адрес можно поменять на форме.
Изменения полей формы пока не сохраняются.

## Доступ и границы первой версии

Административный API требует персональный Bearer-ключ и право CanRead.
Сервер хранит только SHA-256 случайного ключа, имя пользователя и право чтения.
Это начальная схема доступа для утилиты; управления учётными записями, входа по паролю
и интеграции с Windows/доменом пока нет.

Действующее ограничение всего API на localhost сохраняется. Поэтому сейчас утилиту запускают
на компьютере сервера. Для удалённого подключения нужны отдельная настройка сетевого доступа
и защищённый транспорт HTTPS; снятие ограничения localhost в эту работу не входит.

Ответ 401 означает, что ключ не принят или пользователь не настроен.
Ответ 403 означает отсутствие права чтения либо запрет нелокального подключения.
Наличие клиента синхронизации никаких административных прав не даёт.

Первая версия предназначена для просмотра. Редактирование настроек, управление папками,
список заданий, изменение истории и восстановление файлов пока не реализованы.

## Расположение кода

- HwSync.Windows.Contract: Common, Client, Administration — контракты двух приложений.
- HwSync.Windows.AppServices: такие же разделы с реализациями и ViewModel; без WPF.
- HwSync.Windows.Client.Application: оболочка клиента синхронизации.
- HwSync.Windows.Admin.Application: оболочка утилиты управления.
- HwSync.Api.Contracts/Administration: переносимые типы административного HTTP API.
- HwSync.Api.Client/AdministrationApiClient: авторизованные HTTP-запросы.
- HwSync.Api: контроллер, обработчик, аутентификация и проверка права чтения.
- HwSync.Persistence.Sqlite/SqliteAdministrationStore: чтение серверной базы через абстракцию.

Windows-приложение получает модель через DI. Административная регистрация не подключает модель
клиента синхронизации, его файловые службы или локальную историю.

## Ключ из переменной окружения

При запуске утилита читает HWSYNC_ADMIN_ACCESS_TOKEN из окружения своего процесса.
В PowerShell перед запуском:

    $env:HWSYNC_ADMIN_ACCESS_TOKEN = "ваш AccessToken"
    dotnet run --project src/HwSync.Windows.Admin.Application

Для запуска из Visual Studio задайте переменную в окружении пользователя Windows,
затем полностью перезапустите Visual Studio, чтобы она передала её приложению.
Не добавляйте настоящий ключ в отслеживаемый launchSettings.json.

Ключ из окружения не отображается в поле формы: можно сразу нажать «Подключить / обновить».
Ручной ввод в поле заменяет загруженный ключ для текущего запуска.
При отсутствии переменной ключ нужно ввести вручную. Изменение окружения требует перезапуска приложения.
Переменная содержит сам AccessToken, а не TokenSha256; настройки пользователя на сервере остаются прежними.
