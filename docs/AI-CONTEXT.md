# HwSync — контекст для продолжения работы

Актуализировано: 2026-09-29. Это краткая карта, а не копия переписки.

## Назначение

Личный проект синхронизации файлов и практического изучения .NET 10. Развиваем небольшими работающими шагами. Читаемость и понятные границы важнее использования всех возможностей библиотек.

## Текущее устройство

- Сервер сейчас на Windows: HwSync.Windows.Server.Host — запуск консолью или службой; общие серверные службы — HwSync.Server.AppServices. Linux — направление развития, отдельный Linux-хост пока не следует считать реализованным.
- HwSync.Core и HwSync.Abstractions отделяют логику и контракты от платформы, UI, HTTP и БД.
- HwSync.Api содержит тонкие контроллеры и обработчики; HwSync.Api.Contracts — отдельные сетевые типы, HwSync.Api.Client — HTTP-клиент.
- Windows-клиент и утилита администрирования — отдельные приложения. Общие контракты и службы находятся в HwSync.Windows.Contract и HwSync.Windows.AppServices.
- SQLite через EF Core хранит собственную историю каждого участника. HwSync.Persistence.Sqlite.Migrations — отдельная библиотека миграций, вызываемая автоматически при старте приложений.
- Переход с прежней SQL-схемы принят через чистую тестовую базу; автоматический перенос старой истории не реализован. Дальнейшие изменения EF-схемы оформляются новыми миграциями.

## Решения и ограничения

- Сравнение пока опирается на относительный путь, размер и время изменения; хеширование содержимого — возможное будущее расширение.
- Решения по файлам задаются профилем и могут уточняться пользователем. Предусмотрены ручные действия и автоматическое выполнение плана; не путать их с полностью завершённым протоколом согласования нескольких участников.
- Требование к конфликтам содержимого: по умолчанию сохранять обе версии; удаление против изменения требует решения пользователя. Реальное подключение конкретных правил проверяй по коду и профильной документации.
- Отсутствующий файл сам по себе не доказывает удаление: важна история успешных снимков. Ошибочное/неполное сканирование нельзя сохранять как пустую папку.
- При сбросе базы теряется память об удалениях. Пользователь это понимает; реальные базы без просьбы не удалять.
- Полное сканирование прерывается при ReparsePoint; обсуждение альтернатив не было разрешением сменить стратегию.
- DevExpress, мобильные приложения с отдельными представлениями для телефона/планшета и Linux-хост — идеи развития, не текущая задача.

## Точка продолжения

Пользователь самостоятельно читает код, задаёт вопросы и просит точечные улучшения. Не начинать новую функциональность без задания. Последние согласованные направления: минимальное применение EF Core, краткая XML-документация и единое читаемое оформление.

## Где читать подробности

- ../AGENTS.md — обязательные правила сотрудничества, кода и проверок.
- DECISIONS.md — принятые решения и их причины.
- CODE-STRUCTURE.md — карта проектов и порядок чтения кода.
- SQLITE-STORAGE.md — схема, миграции, пути и команды EF.
- SYNCHRONIZATION.md — синхронизация и история удалений.
- WINDOWS-CLIENT.md и WINDOWS-ADMIN.md — приложения и настройки.
- HOST.md и REST-API.md — сервер и API.
- ARCHITECTURE.md и ROADMAP.md — архитектурные направления; планы не считать готовой реализацией.

## Продолжение на другом компьютере

Передай код и эти документы через Git: коммит и отправка на исходном ПК, получение изменений на другом. Это делает пользователь либо агент по отдельной просьбе. Без передачи файлов новые договорённости на другом ПК не появятся.

Открой корень репозитория в локальной задаче. Стартовое сообщение: «Прочитай AGENTS.md, docs/AI-CONTEXT.md и docs/DECISIONS.md, проверь состояние репозитория. Продолжаем HwSync; текущая задача: …».

Агенты с поддержкой AGENTS.md получают правила из репозитория; для инструментов с поддержкой Cursor rules есть небольшой указатель .cursor/rules/hwsync-project.mdc. Полная история чата таким способом не переносится. Подхватывание правил зависит от инструмента, поэтому при первом запуске попроси кратко пересказать договорённости.
